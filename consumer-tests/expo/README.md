# consumer-tests/expo

An Expo app on Expo SDK 56, the oldest the SDK supports, that installs
`@coproduct/react-native-sdk` as a packed tarball. It catches what only an Expo
app can surface: the SDK's config plugin, Expo autolinking, and native projects
generated by `npx expo prebuild` rather than checked in.

It installs `expo-iap`, not `react-native-iap`, so its paywall bridge loads the
Expo purchase library. It installs `@react-native-community/geolocation`, so
the location peer is linked and built, and it lists every onboarding permission in the SDK's
config plugin beside the bare `react-native-permissions` entry `npx expo
install` adds.

## Toolchain

Node 22 or later, CocoaPods, Xcode 26+, JDK 17, and the Android SDK.

## Run

```bash
npm run setup         # packs the SDK at ../../sdks/react-native/coproduct and installs
npm run prebuild      # writes ios/ and android/ from app.json
npm run ios           # or: npm run android
```

`scripts/build/artifact-linked-expo-consumer-test-ios.sh` and
`scripts/build/artifact-linked-expo-consumer-test-android.sh` run the same
steps as the release gate, and check that prebuild wrote what the config
plugin asks for.

## Verifying green

The screen prints five status lines, and the app logs them as one
`COPRODUCT_EXPO_CONSUMER_STATUS` line. All must be true:

- SDK ready: yes
- Host callbacks: yes
- getBool: false
- Observer registered: yes
- Purchase library: expo-iap
